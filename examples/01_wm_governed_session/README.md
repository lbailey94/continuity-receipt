# Example 01: captured Gen2 receipt and modeled Gen3 compatibility fixtures

This directory is local, untracked work in progress. It is not in the public repository, signed v0.4.0 tag, or published packages.

- gen2_governed_bundle.json is byte identical to the captured WhiteMagic WMv9 S2 governed bundle at receipts/s2_mandala_pass_20260922/governed-bundle.json (SHA-256: 1421028bb0f2e0015693328788ce910c5e792b34fc5a0addecc53f92f0fffd6e). It is a runtime-produced record, though the verifier alone cannot corroborate the narrated dispatch.
- gen3_intake_bundle.json is generated by tools/cross_verification_scoreboard1.py from modeled Gen3 facts using a deterministic test key. It is a format compatibility fixture, **not a receipt emitted by the Gen3 runtime**.
- gen3_redacted_bundle.json is the same modeled fixture after selective redaction and disclosure. It is not an independent runtime artifact.

All three use spec 0.2. They do not exercise the new 0.4 agreement binding or the 0.5 development candidate. The deterministic Gen3 signing key is public test material and must never be used for real receipts.

From the repository root, verify each file with Python:

```sh
for f in examples/01_wm_governed_session/*bundle.json; do
  continuity-receipt-verify "$f"
done
```

To verify with Rust from a checkout, use:

```sh
cargo run --manifest-path rust/Cargo.toml --bin continuity-receipt-verify -- examples/01_wm_governed_session/gen2_governed_bundle.json
cargo run --manifest-path rust/Cargo.toml --bin continuity-receipt-verify -- examples/01_wm_governed_session/gen3_intake_bundle.json
cargo run --manifest-path rust/Cargo.toml --bin continuity-receipt-verify -- examples/01_wm_governed_session/gen3_redacted_bundle.json
```

A TRUSTED result establishes signature, chain, and format checks under the supplied policy. It does not establish that the modeled Gen3 events happened or that the captured Gen2 runtime enforced the claims in its body.

Before publishing this example, capture a Gen3-produced bundle and record its emitter commit, exact input, output digest, and independently run verifier results. The current provenance.json contains assertions from the generator and is not independent evidence of those facts.
